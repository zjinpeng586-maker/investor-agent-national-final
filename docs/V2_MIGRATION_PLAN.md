# 财报智问 V2.0 迁移计划

## 原则

这是对国赛 V1.0 的升级，不是另起一个完全独立项目。

优先：
- 保住已经跑通的真实能力
- 调整信息架构
- 再增强智能问数能力

禁止为了“代码更漂亮”在截止日前做无必要的大规模重构。

## Phase 0 — 基线与规范

目标：
- 冻结 `main`
- 建立 `internet-plus-v2`
- 补充 V2 需求、UI、验收规范
- 确认依赖、测试与 Streamlit 能启动

本阶段不改业务功能。

## Phase 1 — UI 与信息架构

目标：
- 从七个横向 Tab 改为五个一级入口
- 财报问数成为默认首页
- 迁移企业分析相关入口
- 迁移数据中心相关入口
- 保持 V1.0 后端能力可用

优先复用：
- `core/db.py`
- `core/service.py`
- `core/parsers.py`
- `core/analysis.py`
- `core/qa_engine.py`
- `core/online_disclosure.py`
- `core/report_pdf.py`

除非确有必要，不重写这些稳定模块。

## Phase 2 — 财报问数主链路

目标：
- 自然语言问题
- 企业 / 年份 / 指标识别
- 多轮上下文
- 条件修改
- 主动澄清
- 结果卡片统一输出
- 查询过程展示

此阶段必须让比赛核心演示链路稳定。

## Phase 3 — Text-to-SQL 与校验

目标：
- 从自然语言生成结构化查询
- 限制只读查询
- 检查字段 / 表 / 条件
- 查询失败时修正
- 结果合理性检查
- 对用户展示必要的查询过程

先做可控、可解释、可测试的范围，不追求覆盖所有 SQL。

## Phase 4 — 研究资料库 / RAG / 复杂任务

目标：
- 年报 / 研报检索
- 文档原文与页码
- 证据引用
- 财务数据 + 文档证据融合
- 复杂任务拆解

复杂任务示例：
“筛选营收增长但现金流下降的公司，并结合行业研报解释原因。”

## Phase 5 — 评测与部署

目标：
- 标准测试题
- 真实评测结果
- 错误案例
- 性能与稳定性检查
- Streamlit Cloud 部署
- 比赛演示回归

截止日前最后一天原则：
**只修 Bug，不再新增非必要功能。**

## 迁移时不得丢失

每一阶段完成后都要回归：

- 公开披露检索
- PDF / Excel / CSV 导入
- 企业分析
- 企业对比
- 图表
- 风险规则
- 来源追溯
- PDF 报告
- 本地模式
- 云端增强模式

## 当前已知部署技术债

后续按优先级处理：
- Python 运行版本统一
- requirements 版本漂移
- pytest 自动测试为空
- `fitz` 弃用
- SQLite / 上传文件的 Cloud 持久化
- 多用户数据隔离
- 外部披露站点稳定性

这些问题要解决，但不能阻塞 P0 比赛主链路。
