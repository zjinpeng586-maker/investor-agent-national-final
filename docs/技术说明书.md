# 财报智问参赛作品技术说明书

版本 2026 年 9 月 25 日

本作品面向公开财务信息的查询与解释，将结构化财务指标、报告原文与可追溯的处理过程放在同一界面。评审可从一次净利润原因提问开始，检查指标变化、文档依据和查询路径，再通过评测中心复核固定测试结果。

本版本已完成本地代码回归，448 项测试通过，固定评测 55 项通过。上述结果针对指定测试集，不代表任意财报的解析准确率，也不构成投资建议。线上托管、真实设备和外部接口可用性需分别验收。

## 一 作品范围与使用路径

作品采用 Streamlit 构建五个页面，覆盖首页、财报问数、企业分析、数据中心和评测中心。财报问数承接自然语言问题与多轮上下文，企业分析组织企业指标和报告输出，数据中心管理资料接入与复核，评测中心在独立临时数据库运行回归用例。浅色与深色界面共用业务流程。

演示建议先询问“比亚迪2024年营业收入是多少？”，观察结构化答案与来源，再询问“比亚迪2024年净利润为什么变化？”，查看答案摘要下方的“数因融合财务归因”。归因树不是独立一级页面；普通数值查询不会自动生成归因树。

企业、年度和资料范围直接影响可回答性。缺少结构化数据时系统不能凭报告语气补造财务数字；缺少真实年报时可以展示量化变化，但必须说明未取得足够解释证据。

## 二 系统架构与数据流

展示层由 app/main.py、app/styles.css 和 app/ui_state.py 组成，负责页面、主题、交互和会话状态。问答编排位于 core/qa_engine.py，由 core/planner.py 选择结构化查询、文档检索或混合路径。core/conversation.py 管理多轮问题中的企业、年度和指标上下文。

结构化路径通过 core/text_to_sql.py 构造和校验受约束的查询计划，再读取 SQLite 数据。其核心并非允许语言模型任意执行 SQL，而是限制查询结构、字段和企业年度范围，并验证返回结果。异常或不完整结果不直接变成确定性结论。

文档路径由 core/retrieval.py 完成 PDF 文本分段、关键词相关性检索和来源约束。当前实现是本地文本检索，不宣称采用向量数据库或训练专用金融模型。混合路径将结构化事实与报告片段组合，保留文件名、报告年度和 PDF 页码供复核。

core/attribution.py 复用已有安全查询与检索组件，不创建另一套数据库或不受控查询通道。企业分析和 PDF 输出使用既有分析与报告模块。可选云端模型用于表达增强，其输出受到事实一致性检查约束；未配置模型密钥时，离线规则与结构化查询仍可运行。

## 三 数据口径与接入管理

financial_metrics 保存营业收入 revenue、归母净利润 net_profit、经营现金流 operating_cashflow、净资产收益率 roe、资产负债率 debt_ratio、毛利率 gross_margin 和每股收益 eps。金额指标展示口径为亿元，比例指标为百分比，每股收益为元。导入环节需要识别并转换原始单位，不能将万元与亿元直接比较。

数据接入采用预览、校验与确认流程，保留逐指标来源及报告资料。公司与报告期检查用于防止企业混淆、年度串用和季度数据冒充全年数据。文件指纹用于识别重复内容；不能可靠解析的值应保留缺失状态，不能自动补为零。

公共部署采用独立会话资料库，支持检索公开披露、下载复核和真实入库，并由同会话问数、企业分析与归因读取。每会话最多20个文件、100 MB，访客间数据库与附件隔离，不迁移服务器旧库。会话刷新、断线或重启后不保证恢复。本地运行保留持久化统一资料库；显式 readonly 模式仍禁止写入。最新增强版验收见 docs/在线披露增强验收.md。

## 四 数因融合财务归因树

归因树定位为财务变化线索组织工具。SQL 回答发生了什么，报告检索回答原文如何解释；两者相互补充，但不形成严格因果模型。系统不生成因果概率或未经模型支持的因素贡献率。

当前支持单家企业、年度净利润以及单一目标年度或连续两个年度。只问目标年度时，归因模块额外查询上一年与目标年，读取净利润、营业收入、毛利率和经营现金流。主问题的查询年度范围保持不变，额外使用的比较基期在归因结果中披露。

根节点展示归母净利润变化。营业收入和毛利率节点表示经营与盈利能力线索；经营现金流节点仅表示经营质量辅助线索，不能直接解释为利润变化原因。毛利率差异以百分点表示。上年为零时不计算同比比例，上年为负时明确以上年绝对值为基数，避免“扭亏增长率”被误读。

归因证据必须与企业、目标年度和指标匹配，包含有效文件与 PDF 页码，并在片段中直接解释相应指标变化。半年报、季报以及明确描述其他年度的句子不能用于解释全年目标年度。文件名不足以证明报告期时，还需检查文档标题和片段。

内置样本中，比亚迪净利润从 2023 年 300.41 亿元变为 2024 年 402.54 亿元，按样本精度计算约增加 34.00%。这是演示数据口径，不能替代原始报告的完整精度。没有对应原文时应显示“当前仅形成量化归因线索，未检索到足够的同年度报告解释证据”。

支持的演示问法包括“比亚迪2024年净利润为什么变化？”、“比亚迪2024年净利润增长的主要原因是什么？”和“比亚迪2024年净利润归因分析”。多企业、季度或半年归因不属于本版支持范围。

## 五 安全与可靠性边界

SQL 校验限制可执行的查询，配合企业、年度和返回值校验，避免越界结果进入答案。下载模块对地址、解析后的网络目标、响应大小和耗时设置约束。来源预览限制在当前资料库范围内，不能把任意服务器路径当作可公开下载的文件。

文件上传、PDF 解析和外部站点下载均可能失败。系统应呈现失败原因或证据不足，而不是把失败转换为虚构引用。扫描件、复杂表格、非常规单位和不完整报告仍需人工复核；本版本不保证通用 OCR 能力。

凭据通过本地环境变量或托管平台密钥配置管理，不随源码包发布。公共演示不需要配置私人业务数据或开放写入权限。服务器日志、会话信息和备份也应按实际部署范围保护。

## 六 测试结果与修复记录

2026 年 9 月 25 日，在 macOS 与 Python 3.12 环境运行全量自动测试，448 项通过，保留 5 项 PyMuPDF 底层 SWIG 弃用警告。语法编译检查通过，固定 Benchmark 55 项通过、0 项失败。Streamlit 本地健康接口和根页面返回 HTTP 200。健康响应仅证明服务启动，不替代页面交互验收。

本次新增 17 项回归用例，覆盖解释意图、纯指标定义、同比零值与负值等边界、包含“报告”字样的原因问法，以及非年度报告的证据拒绝。修复后原因问答摘要与归因树共用校验后的比较数值，避免摘要称数据不足而树中已有同比的矛盾。

本轮还统一“为何”“归因”等解释词识别，避免“主要原因是什么”被当作指标定义；排除半年报和季报进入年度证据；升级检索缓存版本以触发重新校验。评测命令的依赖警告输出与 JSON 结果分离，便于自动化读取。以上调整不修改数据库结构和七项指标口径。

测试覆盖既有界面 AppTest、查询安全、资料导入、证据来源、历史会话与 PDF 输出相关逻辑。固定测试全部通过不能证明不存在未知缺陷；真实云端模型、公网数据源、生产并发和真实 Windows 安装不在本次本地实测结论内。

## 七 复现与发布管理

Windows 与 macOS 安装、启动、备份、恢复和排错说明统一位于 README。启动入口为 app/main.py，依赖使用 requirements.txt 的固定版本。安装脚本以 Python 3.11 为目标，本轮实际执行回归的解释器为 Python 3.12，应区分脚本目标与已测试环境。

源代码封板包包含 RELEASE_MANIFEST.json，记录各文件大小与 SHA256，便于核验交付内容。包内不包含虚拟环境、运行数据库、上传资料、缓存和私人密钥。既有 docs/validation 记录保留历史属性，本次结论以 20260925归因问答修复与验收.md 为准。

发布采用独立正式分支与明确提交，不覆盖删除 main。旧发布分支和 archive 回滚分支保留。在线环境应绑定明确发布分支，更新后重新检查首页、问数、归因、企业分析和评测中心；桌面与移动视口分别执行，不能以窗口可打开代替功能可用。

## 八 已知限制

归因树仅支持目前已定义的年度净利润场景，不提供严格因果贡献率。缺失原文的节点只有量化线索。PDF 页码是实际文件页序，可能与印刷页码不同。

本地演示数据与固定摘页用于可复现验证，不代表全市场数据覆盖。离线文本检索可能遗漏同义表达；真实复杂报告需要复核。线上服务还受到托管资源、网络访问、外部 API 和休眠策略影响。

技术封板表示当前约定范围已完成复核与记录，不表示永久无缺陷。后续出现可复现缺陷时应建立新修复版本、补充测试并保留发布历史。
