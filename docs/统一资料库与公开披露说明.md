# 统一资料库与公开披露说明

本说明适用于 **擎梦数智｜财报智问** 的资料管理与公开披露流程。历史验收文档中的分库行为及测试数量仅代表当时状态；最新验收以对应自动化测试输出为准。

## 运行与权限

产品只有统一资料库，内部 key 固定为 `main`，数据库是 `FINANCIAL_DATA_DIR/main/investor_agent.db`。文件上传、公开披露、主企业/对比企业选择器、普通问答、连续问答、企业分析和数据中心都从这里读取。内置数据也是普通资料，初始化仅补缺失记录，已导入或修正的值和来源保持不变。

本地启动脚本设置 `FINANCIAL_DEPLOYMENT=local`，允许确认入库和删除；公共部署及局域网只读入口仍禁止写操作。只读限制按部署方式决定。`evaluation` 仅为自动评测内部隔离数据库，不是用户可选版本，评测不读写 `main`。

## 旧版本迁移说明

旧版演示资料库 `demo/investor_agent.db` 与个人资料库 `personal/investor_agent.db` 在升级时一次性合并到 `main`：

1. 先合并 `demo`，再合并 `personal`；同企业、年度、指标冲突时后者优先。
2. 使用企业名称、股票代码、年份和指标代码匹配，重新建立企业、指标、来源和报告的关联，不照搬旧自增 ID。
3. 附件复制到 `main`，按内容哈希等稳定标识去重并更新数据库文件路径。
4. 数据合并使用事务；成功后在 `app_meta` 记录 `unified_workspace_migration_v1=done`。重复启动不重复插入，失败不得标记完成。
5. 旧目录保留备份，不自动删除；迁移前应停止旧服务并备份数据。

若 `main` 在迁移前已有非空指标，优先保留这些值。缺少逐指标来源的更早数据库，仅在“企业、报告年份、原文件名或路径”唯一精确匹配时补关联；歧义保持待复核。原附件已经缺失时，迁移详情记录缺失路径，不猜测替代文件。

旧会话中的 `data_workspace`、`active_workspace`、`workspace_sessions` 等字段仅用于兼容清理；新保存的会话不再含切换字段。恢复历史问答仍保留回答快照和多轮上下文。

若只有更早版本的单个数据库，可按 Windows/macOS 说明使用 `scripts/migrate_legacy_data.py` 显式指定原库与附件目录，复制到新的 `main`。来源或单位缺失保持待复核，不伪造旧记录。正常备份默认备份 `main`，恢复只写入不存在的新目录。

## 公开披露的三个阶段

数据中心使用“本地文件接入”“公开披露接入”“数据资产与来源”三个页签。在“公开披露接入”点击“检索公开披露”后，界面显示“正在检索公开披露……”。检索结果保留结构化状态、候选数量、查询条件、成功/失败请求数、耗时与详细诊断。重新检索立即清除旧候选、预览和状态。

| 状态 | 判定和提示 |
| --- | --- |
| `success` | 至少一条候选；部分接口失败不阻断已有候选，另显示警告。提示“检索完成：共获取 {N} 条符合条件的公开披露。”，数量来自实际候选。 |
| `empty` | 至少一个请求正常完成但无候选；提示“检索完成：未获取到符合当前条件的公开披露，请核验企业名称、证券代码、交易所、报告类型及报告期。” |
| `failed` | 全部请求失败或无有效响应；提示“检索失败：{简要原因}。请查看检索详情后重试。”，请求诊断在“检索详情”展开查看。 |

下载并解析成功只生成待确认预览，提示“解析完成：请核验企业、报告期及指标数据，确认无误后执行入库。”，复核后点击“确认入库”。下载失败、PDF 不可读、无法识别企业/年度、缺有效指标或格式不支持均明确显示原因。直接 URL 接入采用同样的阶段区分。

## 入库与企业联动

只有企业、报告文件、来源及至少一项有效年度数值指标写入，事务提交后回查成功，且企业和报告能被业务查询读取，才提示“入库成功”。成功提示包含企业名称以及本次实际新增、更新的财务指标数量。数据库写入失败回滚，不留下孤立来源或半条记录。找到候选、下载完成和预览均不会新增可分析企业。

`commit_import` 区分 `success`、`document_only`、`unchanged`、`failed`。若事务已经提交而独立回查异常，返回 `verification_failed` 且 `committed=True`，明确提示刷新核查，不声称已经回滚。只有确实未提交写入的失败才提示“本次操作未写入可用分析数据”。重复预览提交或全部已有值被保留时不显示“入库成功”。

Schema 自动升级到版本 3：`report_files` 增加 `source_type`、`source_url`、`report_title`、`report_type`、`import_id`、`content_hash`、`ingest_status`、`metric_count`，旧记录通过真实来源关系回填，正常显示不从 `note` 拆解字段。

仅保存文件而未识别有效年度指标时，数据中心展示“待补充指标”；没有年度数值的企业不进入分析选择器。数据中心的企业、股票代码、文件/披露标题、报告类型、年度、来源类型、来源 URL、状态、指标数量和时间来自数据库。`report_files` 自动增补结构化来源、导入标识、内容哈希、接入状态和指标数量字段，已有数据库幂等升级，无需删除。

成功入库立即重载同一数据库的企业和指标，修正失效选择值并刷新当前页面；单次导入的所有成功企业都可选。主企业从当前对比选项中排除，切换主企业后恢复其对比资格。主企业主动切换同步多轮上下文。股票代码动态读取企业表，新增企业不需要修改代码。删除企业或报告后同样重新查询，避免残留失效选项。

## 验证边界

统一资料库改造时的验收结果和修改文件列表见 [历史改造验收记录](统一资料库改造验收.md)，其中测试数量不替代后续品牌与文案调整的验收结果。

自动化回归使用隔离数据目录；在线接口与异常响应使用 mock，不依赖真实交易所网络，也不读写用户运行资料。真实网络可用性、扫描件/复杂 PDF、macOS 实机与真实云端模型仍需对应环境验证。固定测试通过不代表所有财报都可自动提取完整指标或原因证据。
